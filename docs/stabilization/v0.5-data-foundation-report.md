## 4. Provider truth

### BLS

The adapter maps the fixed CPI and employment series, derives declared MoM/YoY
metrics without discarding source levels/units, chunks public requests, parses
official CPI/Employment Situation schedules in America/New_York and rejects
unsafe point-in-time claims.

Live no-key validation showed that BLS can return official levels while disabling
the requested server-side calculations. The adapter now derives the missing
1-month/12-month percentage changes from those official levels, uses a declared
one-decimal rounding rule, retains the provider warning, and marks the exact
calculation source on every normalized observation. Raw bytes/hash and raw units
remain attached through SourceArtifact/ReleaseValue provenance; these derived
values are never presented as BLS-supplied `pct_changes`.

The BLS Public Data API exposes current/revised history. It is **not** a complete
archive of exactly what was first published at every old release. Capturing a
response now creates a new local vintage; it cannot retroactively manufacture an
old first print.

### Federal Reserve

The adapter and sync service route 2015–2020 to official year-specific archive
pages and use the current calendar for current/future meetings. Future meetings
are persisted with scheduled statement/press-conference stages even before
materials exist. URL, retrieval/publication time and content hash are retained;
`key_qa` and `press_end` are omitted unless a source verifies an exact time.

### FRED/ALFRED

The adapter supports series metadata, observations, realtime periods, vintage
dates and as-of filtering. A FRED API key is required. No live validation or
observed import is claimed for this no-key environment.

### Trading Economics

`Forecast` is treated as survey consensus; `TEForecast` is kept as a distinct
proprietary forecast. The last qualified pre-T0 snapshot is the only eligible
consensus for surprise calculations. Historical PIT access, request quota and
redistribution rights depend on the user's subscription. No live account
entitlement was verified in this worktree.

Scheduled T-24h/T-1h/T-5m/T+5m runs use current capture when executed on time.
Only a missed/delayed historical replay supplies `pit_at` and therefore requires
PIT entitlement. The daily/configuration health path performs no TE calendar
request and records zero request count; a successful consensus sync is the live
health evidence and the operation records quota from the real response.

### Databento

The fixed mappings use `GLBX.MDP3` for CME/CBOT/NYMEX/COMEX products,
`IFUS.IMPACT` for DX and `XCBF.PITCH` for VX. Intraday and daily schemas are kept
distinct and contract resolution belongs in each manifest.

DX/VX are futures, not cash DXY/VIX. ZT/ZN are Treasury-futures price proxies and
must not be labelled as exact 2Y/10Y cash-yield basis-point changes.

Databento/Trading Economics raw account data is local provenance material. It is
not committed or returned for redistribution.

## 5. Cost and execution safety

There are four independent gates for a paid Databento path:

1. `WORLDSTATE_ALLOW_PAID_DOWNLOAD=true` must be an explicit opt-in.
2. A configured credential and required dataset entitlement must exist.
3. Every paid slice must have a fresh, high-confidence Databento metadata quote;
   a fallback record estimate can never authorize execution.
4. The slice and the cumulative cross-release estimate must not exceed
   `WORLDSTATE_DATABENTO_MAX_ESTIMATED_COST_USD`.

The `/v2/data/backfill/estimate` response currently uses existing local
manifests and, in setup/no-key mode, a bounded record-count fallback calculation.
It is not a Databento invoice quote. Before provider I/O, the worker obtains and
validates the real metadata quote for the complete release batch, passes the
remaining aggregate budget across releases and stops after a paid-slice failure
because the final billable amount is then unknown. The API recomputes estimates
and does not trust a browser-supplied estimate ID.

`POST /v2/data/backfill` persists an idempotent approved/rejected task record.
When the local scheduler is enabled, a recoverable worker claims approved jobs,
checks the gates again before provider IO, records progress/partial results and
reuses existing manifests. Missing keys or inputs produce explicit blockers;
they do not erase already persisted stages.

## 6. API and UI

Implemented read endpoints:

- `GET /v2/data/providers`
- `GET /v2/data/coverage`
- `GET /v2/data/backfill/estimate`
- `GET /v2/data/backfill/{id}`

Implemented write-protected job endpoints:

- `POST /v2/data/backfill`
- `POST /v2/data/backfill/{id}/cancel`

Provider status distinguishes public/configured/unconfigured and returns no
credential. Coverage is separated by `observed` or `fixture`; an observed view
does not count fixtures. Each dimension separately reports rows that are merely
stored and rows that pass the shared analysis selector. A revised current BLS
value, post-T0 consensus, or unreconciled market manifest can therefore be
`stored_not_eligible` instead of falsely appearing analysis-ready.

The existing Data & Methods and Event Lab views display Provider configuration,
quota/entitlement/health where known, coverage gaps, cost estimates/jobs and
release provenance/data mode. This scope did not add a new macro event or a new
workspace.

Today and Regime now use a stricter read policy: observed mode excludes fixture
rows, future/scheduled releases, pending or legacy-incomplete runs, and any
analysis without a reproducibility-complete manifest. The Releases view keeps
pending, fixture and non-reproducible states visibly distinct. The API exposes
the selected `data_mode` and eligibility policy rather than implying that a
release row is a completed study.

## 7. CLI and scheduler boundary

Implemented operational diagnostics and actions:

- `data-doctor`
- `data-status`
- `estimate-backfill`
- `backfill` (server-side estimate plus durable worker job)

The stable command names `sync-official`, `sync-calendar`,
`snapshot-consensus`, `sync-market` and `reconcile-data` invoke the durable
services and return `completed`, `partial` or `blocked` under one documented
HTTP/CLI status contract. They never substitute fixture for missing observed
inputs.

`WORLDSTATE_SCHEDULER_ENABLED=true` starts non-blocking scheduler and backfill
tasks with the API. Daily jobs include quota-free provider configuration health,
official/calendar sync and overnight reconciliation; event-relative jobs cover
consensus, official refresh, minute market completion and deferred long windows.
First startup catches up today's missed daily jobs once, every cycle recovers
newly stale attempts, and network failure cannot block desktop health/startup.
Provider states such as missing credentials, missing entitlement and paid
download disabled are stored as `blocked`/`partial` outcomes, not scheduler
failures. The v0.5.1 migration reclassified matching legacy scheduler noise in
place while retaining its original error text in `output_json`.

## 8. Data mode and quality

- Demo startup is opt-in (`WORLDSTATE_DEMO_MODE=false` by default).
- Explicit `bootstrap` creates fixture demonstrations.
- Fixture and observed data can coexist but cannot satisfy each other's coverage
  or historical cohort.
- `observed` does not imply official, verified, first-release or complete.
- Provider health, entitlement, quota, quality grade, coverage and contamination
  are independent fields.
- Raw artifact hashes and market/calendar manifests support provenance, but a
  manifest does not repair missing or unlicensed data.
- An AnalysisRun only consumes release-linked manifest ranges. One deterministic
  provider/contract/dataset/schema identity is selected per instrument and
  granularity; selected manifest IDs and bars are frozen into the run snapshot.
- One-minute bars drive short windows. Long T+1/T+5/session outcomes require a
  daily or declared session-close value. Databento `ohlcv-1d` is a UTC-day
  aggregate, capped at grade C and labelled experimental—not an exchange close
  or settlement. Missing/unknown daily semantics yield a data gap, not a return.

## 10. Known blockers and risks

1. FRED, TE and Databento keys are absent in the validation environment; TE PIT
   and Databento entitlements cannot be inferred from adapter tests. BLS needs no
   key in public mode, but its schedule HTML returned HTTP 403 on this network.
2. BLS cannot supply a complete historical first-release vintage archive.
3. Consensus/history availability and legal redistribution rights depend on the
   user's licensed sources.
4. `exchange-session-lite` remains experimental and is not a complete exchange
   calendar/roll/settlement implementation.
5. Databento contract/continuous mapping needs real-account validation before a
   historical research result can be called production quality.
6. The local async scheduler only runs while the Research API is open; it is not
   a cloud daemon. Catch-up is bounded and cannot manufacture missed current
   snapshots without licensed PIT replay.
7. The desktop build still relies on local Python and is not a signed standalone
   installer.
