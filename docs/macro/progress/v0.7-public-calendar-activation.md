# v0.7 public BLS calendar activation

Date: 2026-08-12  
Scope: automatic pre-T0 release scheduling only

## Implemented

`BlsOfficialProvider.fetch_schedule()` uses the official BLS public ICS feed
(`https://www.bls.gov/schedule/news_release/bls.ics`) for the current and
forward calendar.  It parses CPI and Employment Situation events, preserves
the title-supplied reference period, handles `America/New_York` DST, and
captures a durable source artifact with its hash and retrieval time.  The
official schedule HTML remains a secondary fallback and is labelled as such
in artifact and calendar-snapshot metadata.

`sync_bls_calendar` creates or updates an observed `MacroRelease` and its
`release` stage idempotently when the event contains a reference period.  An
ICS event without a period is retained only in the calendar snapshot; the
service does not invent a period label.

## Current external blocker

On the runtime network, both official BLS endpoints returned HTTP 403.  The
service reports `provider_public_calendar_unavailable`, rather than treating
the public calendar as a BLS API entitlement.  The runtime therefore contains
zero observed CPI rows for `2026-07`; no manual import was used.  Once an
allowed route can reach either official endpoint, rerunning the same command
will perform the normal observed upsert without code changes.

Consensus capture and market-minute download are deliberately not run until
the official release identity exists.
