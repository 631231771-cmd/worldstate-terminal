T0: `2026-08-12T12:30:00Z`

## Correctness changes

- Actual readiness now uses the analysis engine's canonical release-value
  selector.  Actual values are release facts and may be captured after T0;
  pre-T0 capture is only a consensus requirement.  Initial values remain
  preferred, superseded values are excluded, and current-version BLS rows that
  cannot reconstruct the initial print remain ineligible.
- Added `ConsensusEligibility` v1.  It reports eligibility, reasons,
  limitations, source semantics, capture transport, and provenance completeness
  without changing stored consensus values or timestamps.  A quality `D` row is
  neither automatically accepted nor rejected: the explicit browser-capture
  policy can accept it with a limitation; an unapproved `D` remains blocked.
- Every release-linked one-minute manifest is checked before readiness, without
  filtering by the product asset list.  Legacy manifests without the supported
  `event-intraday-v1` policy are rejected.

## Runtime preflight

The CPI release has four observed pre-T0 consensus rows.  All four are eligible
under `consensus-eligibility-v1`, with explicit limitations for browser capture
and quality `D`.  Actual readiness is currently false because BLS actual values
have not been captured; market readiness is false because there are no eligible
minute manifests.  Overall readiness is therefore correctly false.

No values, capture timestamps, consensus rows, actuals, AnalysisRun, or
Databento data were changed or created by this preflight.
