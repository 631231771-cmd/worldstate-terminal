# WorldState v0.6 — Operational Macro Intelligence

v0.6 turns the v0.5 research API into a daily local macro terminal. The
existing release/event engine remains the source of truth for CPI, NFP and
FOMC research. v0.6 adds deterministic read-side projections on top of the
same point-in-time Series, Observation, MarketBar and Evidence records.

## Daily workflow

1. Open `WorldStateApp.bat` and start on `#today`.
2. Read **World State** for Growth, Inflation, Liquidity, Policy Tightness,
   Credit, Risk, Fiscal and External. Each dimension includes coverage,
   freshness, top drivers, evidence IDs and missing inputs.
3. Read **Top Changes** and **Market Confirmation**. These are ranked clues,
   not unique causal explanations.
4. Open Markets for 1D/1W/1M/3M cross-asset context. Proxy futures and missing
   bars remain labelled.
5. Use Series Explorer to inspect raw values or a reversible transform.
6. Open Releases/Event Lab for the complete Actual → Consensus → Reaction →
   Historical → Evidence chain.
7. Record a personal view in Research → Thesis Book. Evaluation only links
   current state signals to the thesis; it never changes the thesis status.

## API surface

| Endpoint | Purpose |
| --- | --- |
| `GET /v2/world-state` | Point-in-time deterministic state snapshot |
| `GET /v2/daily-brief` | World State, Top Changes, market confirmation, recent/upcoming releases |
| `GET /v2/market-dashboard?horizon=1d\|1w\|1m\|3m` | Cross-asset changes and empirical percentiles |
| `GET /v2/series?q=...` | Series catalog search and latest vintage |
| `GET /v2/series/{canonical_key}?transform=...` | Raw/derived observation history |
| `GET /v2/global-macro` | US/China/Euro Area/Japan/UK coverage map and context cards |
| `GET/POST/PATCH /v2/theses` | User-owned Thesis Book |
| `GET /v2/theses/{id}/evaluate` | Evidence-linked state signals without auto-confirmation |
| `POST /v2/research/assistant/context` | Structured broad-context answer with fact claims |

Every read endpoint accepts `data_mode=observed|fixture|all` where applicable.
The default desktop mode is observed. Demo fixtures use a dedicated provider
and never enter observed queries.

## World State method

The engine groups active Series by `metadata_json.state_dimensions`. For each
series it selects observations whose `available_at` and vintage are no later
than the requested cutoff. It calculates a bounded, sign-oriented change score
from the series' own recent history, then aggregates the dimension with
coverage and freshness. It is not an event `surprise_z`, a forecast or a
trading signal. A dimension with insufficient history is returned as
`score=null` with a missing-input reason.

The first regime label is a transparent Growth × Inflation grid with Policy
and Risk tags. Positive values have dimension-specific meanings (for example,
positive Inflation means hotter inflation and positive Risk means more stress);
there is no global “positive is good” interpretation.

## Truthfulness boundaries

- Fixture, manual, proxy, delayed and unavailable inputs are preserved in
  response metadata.
- AI receives structured state/release/evidence context and may summarize it;
  it may not calculate core numbers, invent sources or emit unique causality.
- Global country rows with no eligible observations are `unavailable`. Context
  cards marked `framework` or `partial` are not live data coverage.
- Market percentiles are empirical over bars currently stored for the requested
  mode. They are suppressed by missing baselines and do not imply a statistical
  forecast.
- Series transforms are presentation-only and do not replace source vintages.

## Current limitations

FRED/ALFRED, Trading Economics and Databento still require the credentials,
entitlements and terms described in the v0.5 data foundation report. BLS
public data can be fetched without a key but schedule access and historical
first-print reconstruction remain environment-dependent. The desktop build
still requires local Python/Node and is not a signed standalone installer.
